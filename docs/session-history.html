1ภาพรวมโปรเจกต์ (จากการอ่าน AGENTS.md / HANDOVER.md / README.md)

SmartGov / Smart SAO — ระบบบริหารงานราชการอิเล็กทรอนิกส์สำหรับ อบต. (องค์การบริหารส่วนตำบล) ของไทย ใช้งานจริงที่ อบต.ลำนางรอง จ.บุรีรัมย์ (39 ผู้ใช้จริง, ทะเบียนน้ำ 2,739 ราย) — ไม่ใช่ระบบทดลอง UI เป็นภาษาไทยเกือบ 100%

4 เว็บในโค้ดชุดเดียว: /login (เจ้าหน้าที่ อบต., JWT หลัก) · /prapa/* (เจ้าหน้าที่ประปา, JWT แยก) · /citizen, /checkbill (ประชาชน ไม่ล็อกอิน) · /hub (เจ้าของระบบ SUPER_ADMIN จัดการหลาย อบต.)

Stack: Next.js 16 + React 19 + Tailwind v4 (frontend, port 3000) / NestJS + TypeORM (backend, port 4000, prefix /v1, synchronize:false → ต้องเขียน migration เอง) / PostgreSQL / ไฟล์แนบเก็บบนดิสก์ STORAGE_DRIVER=fs / deploy self-host Docker Compose บน INET

หัวใจระบบ: สารบรรณ (Correspondence Ticket) — workflow ตายตัว รอดำเนินการ → กำลังดำเนินการ → รอปลัด → รอนายก → เสร็จสิ้น (ห้ามเปลี่ยนลำดับโดยไม่คุยลูกค้าก่อน)

โมดูลที่งานนี้เกี่ยวข้อง: ระบบประปา (/prapa) — จดมิเตอร์ → ออกบิล → จ่าย QR พร้อมเพย์ → แนบสลิป → เจ้าหน้าที่ยืนยัน → ออกใบเสร็จ ใช้งานจริงอยู่แล้ว สร้างขึ้นมาแทนระบบ vendor เดิม (Mongkol Online) ที่ปฏิเสธเชื่อมต่อ

2งาน RFQ ที่ผู้ใช้ต้องเข้าไปทำ

ผู้ใช้ได้รับมอบหมายงานเข้าไปทำให้ ระบบจ่ายค่าน้ำของลูกบ้าน + หน้าร้องทุกข์ ใช้งานได้จริงตาม RFQ ลูกค้า โดยมีลิสต์ "งานที่ทำเสร็จแล้ว" จากคนทำก่อนหน้ามาให้ (ค้นหาบิล/QR/สลิป/ใบเสร็จ/ร้องเรียน พื้นฐานครบ) และ RFQ จริงจากลูกค้า 5 เรื่องหลัก:

  1. ค้นหายอดค่าน้ำด้วยเลขบัตร ปชช./รหัสผู้ใช้น้ำ + นำเข้า/อัปเดตยอดลูกหนี้ผ่าน Excel
  2. QR พร้อมเพย์ตามยอดบิล (เลือกจ่ายหลายบิลได้) + แนบสลิป + หน้าเจ้าหน้าที่ตรวจสลิปเทียบ bank statement + ยืนยันยอด
  3. ใบเสร็จอิเล็กทรอนิกส์ PDF แบบราชการ มีโลโก้/ตราหน่วยงาน ดาวน์โหลด/พิมพ์ได้ทันทีที่ยืนยันยอด
  4. ระบบรับเรื่องร้องทุกข์/ร้องเรียน (แนบรูป+ติดตามสถานะฝั่งประชาชน) + แดชบอร์ดจัดการฝั่งเจ้าหน้าที่
  5. ทดสอบระบบแบบ Local UAT ไล่ทั้ง flow

ผู้ใช้ยังไม่แน่ใจว่ารายละเอียดย่อยอีกชุด (checklist ที่สองที่ได้มา) ต้องทำทั้งหมดไหม — งานนี้คือสิ่งที่ต้องวิเคราะห์แยกว่า อันไหนเป็นโค้ดที่ต้องเขียนจริง อันไหนเป็นงานปฏิบัติ/ตั้งค่า (เช่น ตั้ง PromptPay จริง, ทดสอบพิมพ์เครื่องจริง, ทำเอกสาร UAT)

3ผลสำรวจโค้ดจริง (3 Explore agents + 1 Plan agent)

สำรวจโค้ดจริงแทนการเดา พบว่า ส่วนใหญ่ของ RFQ ทำไปแล้ว — งานที่เหลือคือ "อุดช่องโหว่" ไม่ใช่สร้างใหม่ทั้งหมด:

เรื่องสถานะที่พบจริง
ค้นหาบิล/QR รวมหลายบิล/แนบสลิป/EasySlip auto-verify/staff confirmมีแล้ว ใช้งานได้ แต่มีบั๊ก: จ่าย QR รวมหลายบิลแล้วแนบสลิปได้แค่บิลเดียว ระบบเช็คยอดผิด (mismatch)
ค้นหาด้วยเลขบัตรประชาชนไม่มี ปัจจุบันมีแค่เบอร์โทรอย่างเดียว หรือรหัสผู้ใช้น้ำ+บ้านเลขที่
นำเข้ายอดหนี้ผ่าน Excelไม่มี มีแต่ import ทะเบียนลูกค้า (CSV/JSON, ไม่มีใครเรียกใช้จาก UI) และ import bank statement (คนละเรื่อง)
ใบเสร็จ PDF 58mm + เครื่องพิมพ์ (RawBT)มีแล้ว ครบทั้งออนไลน์(PDF)+เครื่องปริ้น แต่ไม่มีโลโก้ในเทมเพลต (บั๊ก)
หน้าเทียบสลิปกับ bank statementไม่มี มีแค่ auto-verify (EasySlip) กับ bulk reconcile คนละฟีเจอร์
ระบบร้องเรียน (แนบรูป+ติดตามสถานะ+แดชบอร์ด)มีแล้วครบ เป็นระบบทั่วไป แยกจากสารบรรณโดยตั้งใจ

4การตัดสินใจที่ยืนยันกับผู้ใช้แล้ว

ค้นหาประชาชน: ปรับเป็น 2 โหมด ยืนยันตัวตนด้วย 2 ปัจจัยเสมอ — (ก) เบอร์โทร + เลขบัตรประชาชน (แทนที่ "เบอร์โทรอย่างเดียว" เดิม) (ข) รหัสผู้ใช้น้ำ + บ้านเลขที่ (เดิม ไม่แก้)
Excel import: ลูกค้ายังไม่มี template ที่กำหนดตายตัว → mock คอลัมน์ไปก่อน ปรับ header ทีหลังได้ง่าย
ใบเสร็จ: ใช้ 58mm เดิม แค่เพิ่มโลโก้ ไม่ต้องทำ A4
ร้องเรียน: ใช้ระบบทั่วไปที่มีอยู่แล้ว ไม่ต้องทำเพิ่ม

5แผนงานละเอียด (6 workstream)

แผนละเอียดระดับไฟล์/ฟังก์ชันที่ต้องแก้ ถูกเขียนไว้แยกเป็นไฟล์อ่านง่ายแล้วที่:

📄 rfq-water-billing-plan.html (อยู่โฟลเดอร์เดียวกันนี้)

สรุปสั้น: WS1 ค้นหา nid · WS2 Excel import (พร้อม dedup) · WS3 หน้าเทียบ bank statement · WS4 แก้บั๊ก QR รวม+สลิป · WS5 เพิ่มโลโก้ใบเสร็จ · WS6 ร้องเรียน (ปิด ไม่ต้องทำ) — เรียงลำดับแนะนำ: WS1 → WS5 → WS4 → WS3 → WS2

ยังไม่ได้ลงมือแก้โค้ดจริง ณ จุดที่บันทึกไฟล์นี้ — เป็นแผนที่ตกลงกันไว้เท่านั้น

6Setup dev environment (จาก git clone ใหม่ ให้รันเหมือนของเดิม)

ก่อนย้ายมาทำที่ C:\smartgov-repo ได้ตรวจ config ของโฟลเดอร์เก่า (ที่รันอยู่จริงตอนนั้น) แล้วสรุปขั้นตอน setup ให้ตรงกัน:

STEP 1 — Infra 
cd infrastructure
docker compose -f docker-compose.dev.yml up -d postgres redis

สตาร์ทแค่ postgres (พอร์ต 5433) + redis (6379) — ไม่ต้อง minio/mailhog/pgadmin เพราะระบบตั้ง STORAGE_DRIVER=fs เก็บไฟล์บนดิสก์ ไม่ได้ใช้ MinIO

STEP 2 — Backend

backend/.env ไม่ติดมากับ git (อยู่ใน .gitignore) ต้องสร้างใหม่ด้วยค่านี้ (ตรงกับที่รันอยู่จริง):

NODE_ENV=development
PORT=4000
APP_URL=http://localhost:4000
FRONTEND_URL=http://localhost:3000

DB_HOST=127.0.0.1
DB_PORT=5433
DB_USERNAME=postgres
DB_PASSWORD=devpassword
DB_DATABASE=smartgov_dev
DB_SYNCHRONIZE=false
DB_LOGGING=false

JWT_SECRET=your-super-secret-jwt-key-change-in-production
JWT_EXPIRES_IN=15m
JWT_REFRESH_SECRET=your-super-secret-refresh-key-change-in-production
JWT_REFRESH_EXPIRES_IN=7d

REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_PASSWORD=
REDIS_DB=0

THROTTLE_TTL=60000
THROTTLE_LIMIT=100
MAX_FILE_SIZE_MB=50
ALLOWED_FILE_TYPES=pdf,docx,xlsx,jpg,jpeg,png,zip

PUPPETEER_EXECUTABLE_PATH=

INITIAL_ADMIN_USERNAME=admin
INITIAL_ADMIN_EMAIL=admin@smartgov.local
INITIAL_ADMIN_PASSWORD=Admin@123456

STORAGE_DRIVER=fs
STORAGE_FS_ROOT=.storage

⚠️ PUPPETEER_EXECUTABLE_PATH เดิมชี้ path Linux — บน Windows dev เว้นว่างไว้ (ใช้ Chromium ที่ puppeteer ดาวน์โหลดเอง) หรือชี้ chrome.exe จริง

cd backend
npm install
npm run migration:run
npm run seed:run
npm run start:dev        # http://localhost:4000/v1
STEP 3 — Frontend

ไม่ต้องสร้าง .env.local — โค้ด default ชี้ http://localhost:4000/v1 อยู่แล้ว

cd frontend
npm install
npm run dev               # http://localhost:3000
STEP 4 — ล็อกอินทดสอบ

admin / Admin@123456

ข้อควรรู้เพิ่ม

  • backend/.env, backend/.storage/ (ไฟล์แนบเดิม), node_modules/ ไม่ติดมากับ git clone — ถ้าอยากได้ไฟล์แนบเดิม ต้องคัดลอก .storage จากโฟลเดอร์เก่ามาเอง
  • ถ้าอยากได้ข้อมูลฐานข้อมูลเดิมเป๊ะๆ (ไม่ใช่แค่ schema+seed ใหม่) ต้อง pg_dump/pg_restore ไม่ใช่แค่ migration+seed
  • ถ้ารันคู่กับโฟลเดอร์เก่าที่ยังเปิดอยู่ ต้องปิดก่อนหรือเปลี่ยนพอร์ต ไม่งั้นชนพอร์ต 4000/3000/5433/6379

→ขั้นต่อไป

  1. Setup dev environment ในโฟลเดอร์ C:\smartgov-repo ให้รันได้ก่อน (ดูขั้นตอนข้างบน)
  2. เริ่มลงมือทำตามแผน rfq-water-billing-plan.html — แนะนำเริ่มจาก Workstream 1 หรือ 5 (เล็กสุด ไม่พึ่งใคร)
  3. ทดสอบทุก workstream ตามหัวข้อ "Verify" ในแผน + รัน node scripts/smoke-saraban-v4.mjs เช็คว่าไม่กระทบสารบรรณเดิม
  4. ปิดงานด้วย checklist ปฏิบัติ (ตั้งค่าจริง/ทดสอบจริง/เอกสาร UAT) ในแผนเดียวกัน
